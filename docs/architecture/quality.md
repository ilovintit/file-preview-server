# 非功能约束与失败恢复

本文件是运行预算与故障处理的权威位置。当前尚无可运行服务、部署规格或测量样本，因此不虚构并发数、延迟 SLO、文件大小上限、可用率或 RPO/RTO 数字。下列约束必须进入 #1 的配置、PR CI 与发布验收；具体数值在固定 fixture 和目标环境测量后记录，未完成前不能宣称达到性能目标。

## 预算与容量

| 预算 | 必须满足的约束 | 验证方法 |
| --- | --- | --- |
| 请求总时间 | 排队/下载/转换/上传/签名共用一个 deadline，不在每次重试重新起算 | 慢源、慢转换、慢存储和客户端取消场景 |
| 依赖时间 | 单依赖 timeout 小于剩余请求时间；入口代理 timeout 大于应用受控截止时间并留出返回错误余量 | 端到端超时与错误响应可见性 |
| lease | 自动续租间隔小于 lease；失去 owner 后禁止发布；请求截止后不再续租 | 杀进程、续租断网、旧持有者迟到提交 |
| 输入/输出体积 | 按实际读取字节限制，不能只信 Content-Length；转换输出和临时目录也有硬上限 | 无长度响应、压缩膨胀、超大输出、临时空间耗尽 |
| 转换并发 | 每 Pod 有界并发和等待队列；副本增加意味着增加 sidecar，不代表共享存储容量同步扩张 | 不同 hash 与同 hash 混合并发，观察队列和存储压力 |
| 清理 | 每批对象数量、并发和重试有上限，失败退避；不阻塞用户请求线程 | 孤儿对象与清理故障注入 |
| 时间 | 统一 Unix 秒边界；时钟明显回拨或共享状态不可靠时关闭受保护请求 | 时间窗边界、时钟偏差和 nonce 状态恢复 |
| 配置 | 启动验证数值正值/上限关系、profile 完整性与 TLS 信任配置；无效配置不进入 ready | 缺配置、非法预算及错误依赖地址 |

发布记录需给出环境规格、fixture 体积/格式、并发模型、缓存命中比例、p50/p95/p99、峰值内存/临时空间、错误率和队列等待，再形成可复现验收门槛。测量使用合成文件，不用生产私有内容；不把测试集结论泛化为所有 Office 排版都一致。

## 故障矩阵

| 故障阶段 | 对外行为（HTTP 定义见 apis） | 状态与恢复 | 必要证据 |
| --- | --- | --- | --- |
| 角色密钥或必需 profile 缺失 | 503，不匿名放行 | 修复启动配置并重验 ready | 配置缺失 API 用例 |
| 验签/时间窗/nonce 失败 | 401，不区分原因 | 不产生 token；修正请求使用新 nonce | 边界与重放用例 |
| Valkey 访问或原子更新失败 | 503；不能确定成功时不返回假成功 | 不回退本地状态；超时后按非幂等签发边界处理 | 断网、写超时和重复签发 |
| 源 URL 失效、重定向失败、源 TLS 异常 | 5xx；不把源站 404 冒充 token 404 | 不创建 ready 产物，释放自身资源 | 可过期源 URL 与重定向 fixture |
| hash/类型/格式不合规 | 422 | 丢弃候选文件，不缓存为成功；修正源或参数 | 内容替换、伪扩展名和坏文件 |
| 等待/转换/上传超时或故障 | 5xx | 不无限等待；按 owner、generation 和维护记录恢复 | 依赖延迟/中断注入 |
| 对象已上传但发布失败 | 5xx | 孤儿可回收，不能返回未发布引用 | 部分成功故障注入 |
| ready 引用指向缺失对象 | 不发已知无效短链 | 条件失效旧 generation；在期限/预算允许且源仍可读时重建，否则返回 5xx；重建不得重新起算签发时的缓存期限 | 对象外部删除、源 URL 已过期 |
| token 转换中到期/撤销 | 发送前复查；后续解析 404 | 文件工作可能已发生，不能复活 token；在途竞态见 runtime | 交错调度测试 |
| 清理删除失败 | 不复活过期缓存；用户链路与清理分离 | 维护记录保留，幂等重试，积压告警 | 删除拒绝/超时与重启恢复 |
| H5 网络/CORS/Range 失败 | 展示端错误反馈，不造服务端 404 | 按 clients 重新分类并重试原 token URL | 真实浏览器与微信平台验证 |

所有文件只在缓存未命中时依赖源站可达性；首次下载源 URL 已过期、内容不一致或存储故障仍可能令预览失败。cache_ttl ≥ ttl 解决正常状态的期限冲突，不是端到端可用性保证；缓存命中可复用本 profile 已校验的内容，无须重新下载源站。

## 状态丢失与恢复界限

token、nonce 与缓存索引虽然都在 Valkey，可靠性要求不同。缓存可从源重新生成；token 丢失使旧链接失效；nonce 丢失却可能允许重放，不能把三者统一当成可任意淘汰的缓存。部署必须避免静默淘汰有效 nonce，容量耗尽时拒绝写入并告警。副本切换或备份恢复若无法证明 nonce 连续性，应暂停受保护入口，覆盖残余验签窗口或按安全流程轮换受影响 key 后再开放。

token 恢复可能重新引入已撤销记录，因此不能盲目把旧快照当作授权真相。恢复方案默认不承诺旧 token 继续有效，须由基础设施侧在 #1/发布验证失效处理与调用方重新签发路径。原生 App、异地多活、分片容量与跨地域恢复均无本期验收承诺，不通过引入新中间件补齐未知要求。
